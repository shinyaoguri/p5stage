# 0009: GitHub のアクセストークンはサーバ側に封じ、ブラウザにはセッション ID だけを渡す

## 状態

採用 (2026-08-12)

## 文脈

Phase 2 で GitHub OAuth (scope=gist) を入れる。移植元の canvastage は、取得した
アクセストークンを **popup の postMessage で受け取り localStorage に保存**し、
ブラウザから直接 GitHub API を叩いていた (`token-store.ts` / `github-auth.ts`)。

p5stage でこの方式をそのまま引き継ぐには無理がある。

- **`gist` scope はユーザーの全 Gist への書き込み権限**を持つ (要件 3.6 / ADR 0002)。
  漏れた場合の被害は p5stage の中に閉じず、その人の GitHub アカウント全体に及ぶ
- p5stage は**他者の書いたコードを実行するサービス**で、XSS の面積が普通のアプリより広い。
  本体オリジンに 1 つでも穴が空けば、localStorage のトークンは全て読める
  (実行 iframe は別オリジンに隔離してあるが、隔離は「本体 ⇄ preview」の境界であって、
  本体側の XSS を防ぐものではない)
- ADR 0008 でセッションを `__Host-` cookie に寄せると決めた。トークンだけ localStorage に
  残すと、守り方が 2 系統に割れる

## 決定

**トークンはサーバ側だけが持つ。ブラウザに渡すのはセッション ID だけにする。**

1. **保管場所は D1**。KV は結果整合性でログアウトの反映が遅れる。D1 なら失効が即座に効く。
   Phase 2 でどのみち D1 が要る (作品メタデータ) ので依存も増えない
2. **cookie に載せるのはセッション ID だけ**。`__Host-` プレフィックス付き、`Secure` /
   `HttpOnly` / `Path=/` / `SameSite=Lax`、`Domain` 属性なし (ADR 0008)
3. **DB に保存するのは cookie の値そのものではなく、その SHA-256**。DB のダンプが漏れても
   セッションを乗っ取れない。突き合わせは毎回ハッシュして引く
4. **アクセストークンは AES-GCM で暗号化して保存する**。鍵は `GITHUB_CLIENT_SECRET` から
   HKDF で導出し (`info` で用途を分離)、**専用の secret を増やさない**。
   Client Secret をロテートすると既存セッションは復号できなくなるが、そのときは
   再ログインで復旧する (ロテートは稀で、全セッション失効はむしろ望ましい挙動)
5. **GitHub API は Worker が代理で叩く**。ブラウザはトークンを一切見ない。
   要件 5.2 の「閲覧者トラフィックを GitHub に直接流さない」とも同じ向きになる
6. **OAuth の往復は popup ではなくトップレベルリダイレクト**にする。cookie を確実に載せられ、
   ポップアップブロックの考慮も、`postMessage` でトークンを渡す経路も要らなくなる。
   編集中の内容は Phase 1-6 のドラフト (IndexedDB) が持っているので、離脱して戻っても失われない

## 影響

- **ブラウザに漏れうるトークンが存在しない**。XSS を踏んでも、攻撃者が得られるのは
  「そのセッションで p5stage 越しに Gist を操作できる」ことまでで、GitHub の生トークンは出ない。
  セッションはサーバ側で即座に失効させられる
- canvastage の `token-store.ts` は使わない。`github-auth.ts` も popup 前提なので骨格だけ参考にする
- **Gist を触る処理はすべて Worker 側の口を経由する**。クライアントから直接叩けないぶん
  API ルートが増えるが、レート制限の遵守 (要件 5.2 の mutative 1 req/s) を
  サーバ側で一元的に守れる形になる
- Client Secret のロテート手順に「全ユーザーが再ログインになる」ことを明記する必要がある
- Astro 組み込みの `session` 機能 (KV バインディングを要求する) は使わない。
  セッション ID のハッシュ化とトークンの封筒を自前で制御したいため、
  `astro.config.mjs` の `session: false` はそのまま維持する
