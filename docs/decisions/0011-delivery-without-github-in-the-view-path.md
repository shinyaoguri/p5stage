# 0011: 閲覧経路から GitHub を外し、作品 URL は ID を正・login を飾りにする

## 状態

採用 (2026-08-12)

## 文脈

Phase 2-4 で作品ページ (`実行 + コード表示 + メタ情報`、閲覧はログイン不要 — 要件 3.4) を
作る。ここで初めて「作者以外が中身を読む」経路が生まれ、2 つ答えが要る。

1. **閲覧者はどうやって中身を手に入れるか**。既存の `GET /api/sketches/:id/files` は
   所有者専用で、作者自身のトークンで Gist を読む (ADR 0010)。閲覧者はログインして
   いないので、この口は使えない
2. **作品ページの URL をどうするか**

### GitHub のレート制限が天井を決める

| 資格 | 枠 |
|---|---|
| 匿名 | 60 回/時 **per IP**。Workers の出口 IP は他の Cloudflare 顧客と共有 |
| 利用者のトークン | 5,000 回/時/人 |
| OAuth App の client credentials (Basic 認証) | **5,000 回/時/app** |

条件付き GET で 304 が返れば消費はゼロだが、**それが効くのは `Authorization` ヘッダで
認可されている場合だけ**。

閲覧のたびに GitHub を叩く形にすると、匿名なら 1 作品を 1 拠点で見続けるだけで枯れ、
認証付きでも同時に見られている作品が 80 件ほどで天井に当たる。**閲覧数が GitHub の
消費に直結する構造そのもの**が、広く提供することと両立しない。

## 決定

### 1. 閲覧は GitHub を 1 回も叩かない

| 層 | 中身 |
|---|---|
| エッジキャッシュ | 公開作品のページ (`s-maxage=60`) |
| R2 | **リビジョン SHA をキーにした不変オブジェクト** `gists/<gistId>/<sha>.json` |
| D1 | 作品 → 今配るリビジョンのポインタ (`current_revision`) |

閲覧経路は **D1 → R2** で閉じる。GitHub を叩くのは保存のときと、古くなったポインタの
確かめ直しのときだけになり、**消費が閲覧数ではなく保存回数に比例する**。

キーにリビジョン SHA を含めるので、書いたオブジェクトは二度と変わらない。
「古くなった複製」という状態が存在しないため、無効化の仕組みが要らない。
過去リビジョンの再現 (要件 3.2) も、キーを変えるだけで同じ仕組みに乗る。

**R2 に置くのは正本ではなく配信のための写し**。正本は変わらず作者自身の Gist
(ADR 0002) で、失っても取り直せる (実際、写しが無ければ次の閲覧で埋め直す)。

### 2. 鮮度は「保存で進め、閲覧でたまに確かめる」

- **保存時**が主経路。Gist へ書いた後、返ってきた SHA で R2 に書きポインタを進める
- **GitHub 側で直接編集された場合**は自サービスを通らない (Gist に webhook は無い —
  要件 6)。`revision_checked_at` が 10 分より古い作品を閲覧したとき、**表示は
  そのまま返しつつ**裏で条件付き GET を投げてポインタを直す
- **404 が返ったら** `gist_deleted_at` を立てる (tombstone)。以後その作品で GitHub を
  叩かず、ページは「作者が削除しました」を出す

**保存時に書き写すだけ**の設計は採らなかった。それだと GitHub 側の直接編集に永久に
追従できず、写しが古いまま固定される。不変キー + 遅延再検証にすると、その状態が
そもそも作れない。

### 3. 配信のための読み出しは OAuth App の client credentials で行う

閲覧経路にはトークンを持つ人がいない。匿名 (60 回/時/IP) は要件 5.2 の
「未認証アクセスに依存しない」に正面から反するので選ばない。既に持っている
Client ID / Secret で Basic 認証すれば 5,000 回/時/app になり、bot アカウントの新設も要らない。

**書き込みは従来どおり利用者自身のトークン** (要件 5.2)。client credentials を使うのは
公開情報の読み出しに限る。

### 4. 作品 URL は `/@<login>/<sketchId>`。ID が正で login は飾り

実サービスの形:

| | 形 | 作者が改名したとき |
|---|---|---|
| OpenProcessing | `/@<username>/<sketchId>` と `/sketch/<id>` の両方。ID は単独で一意 | — |
| Gist | `/<username>/<gistId>` | **404 になる**。ID 単独形だけが正しく飛ぶ |

`users.login` は改名で変わるので主キーにできない (0001 のスキーマ)。**引く鍵は
sketchId だけで、URL の login は表示のための飾り**にする。

- 正典 URL は `/@<login>/<sketchId>`。`<link rel="canonical">` にも同じ値を出す
- **login が今の持ち主と違えば正典 URL へ 302**。改名しても古いリンクが生きる
  (Gist が踏んだ穴を踏まない)
- `/s/<sketchId>` も受ける。login に依存しない恒久リンクで、常に正典へ 302
- login で D1 を引かないので `users.login` にインデックスは要らない
- `@` を付けるのは、ルート直下の `/<login>/...` が将来のページ (`/about` 等) と
  衝突するのを防ぐため。予約語リストを持たずに済む

### 5. 閲覧画面にエディタを積まない

コードは SSR が `<pre>` に出し、クライアントはその DOM から集めて実行に回す。
同じ中身をページに二重に載せずに済み、JS が動かない環境でもコードは読める。
Monaco (943KB) を閲覧のために配るのは割に合わない (#18)。

## 影響

- **roadmap の 2-4 と 2-5 は統合された**。配信の骨格が無いと作品ページは必ず一度
  壊れた形で本番に出るため。2-5 に挙げていた「条件付き GET・リビジョン SHA キーの
  永続キャッシュ・404 tombstone」はここに入っている
- R2 バケット `p5stage-content` と、CI の `CLOUDFLARE_API_TOKEN` への R2 権限が要る
  (#37 で D1 に対して踏んだのと同種)。ローカルと E2E は miniflare が肩代わりする
- 公開範囲によって配信の扱いが変わる。公開はエッジに載せ、限定公開は
  `private, no-store` + `noindex` (「URL を知る人だけ」は共有キャッシュや検索結果に
  出た時点で崩れる)
- 保存の応答に `published` が増えた。R2 への書き出しに失敗しても**保存は成功のまま**
  返す (Gist には既に書けているので、やり直させる意味が無い)
- 作品ページが**リビジョン単位の URL** を持てる下地ができた。履歴の閲覧 UI (Phase 4) は
  キーを差し替えるだけで載る
