# 0000: 設計判断を ADR として記録する

## 状態

採用 (2026-08-11)

## 文脈

セッションの記憶はいつでもリセットされる前提で、設計判断の経緯をリポジトリ内に
恒久的に残す場所が必要。個人標準 (repo-standards) でも docs/decisions/ の ADR を
推奨しており、手持ちの過半のリポが採用済み。

## 決定

設計判断 (技術選定・アーキテクチャ・運用方針の変更) は docs/decisions/ に
連番の ADR として記録する。各 ADR は 状態 / 文脈 / 決定 / 影響 の 4 節で書く。

## 影響

- 技術スタック選定など今後の判断は、まず ADR に書いてから実装する
- 決定を覆すときは新しい ADR を起こし、古い ADR の状態を「廃止」または「置換」に更新する
