# p5stage 要件定義書

この文書が要件の正本。議論の経緯と根拠は Issue #1 のコメント履歴に残っている。
設計判断の個別の記録は docs/decisions/ (ADR) を参照。

## 1. 目的とポジショニング

OpenProcessing.org のような p5.js コンテンツの開発・共有サービス。
canvastage (透過エディタ) と stagemanager (ビューア) の良いところを取り込んだ**統合上位互換**を目指す。

OpenProcessing との差別化:

- Gist / GitHub との連携 (作品データはユーザー自身の所有物のまま)
- バージョン管理 (Gist リビジョン = 作品の完全なスナップショット履歴)
- ライブコーディング (透過エディタで書きながら見せる + 閲覧者への準リアルタイム同期)

## 2. 用語

| 用語 | 意味 |
|---|---|
| 作品 (スケッチ) | コード一式 + アセット参照 + メタデータ |
| リビジョン | Gist のコミット。コードと assets.json を含む完全なスナップショット |
| blob | R2 上の不変アセット実体。sha256 がキー |
| マニフェスト (assets.json) | ファイル名 → sha256 / size / mime の対応表。Gist に含まれる |

## 3. 機能要件 (v1 / MVP)

### 3.1 エディタ

- 透過 Monaco が実行キャンバスに重なるライブコーディング体験 (canvastage の code-editor / preview / transitions / settings を移植)
- ファイル構成: index.html / style.css / sketch.js を既定とし、任意のテキストファイルを追加可能 (.js / .glsl / .json / .csv 等)。フォルダは無しのフラット構成 (Gist の制約。OpenProcessing のタブ構成と同等の自由度)
- Ctrl/⌘+Enter で即時実行、再実行トランジション
- ドラフト自動保存 (IndexedDB)。canvastage に相当実装は無く新規に作る
  (あちらの IndexedDB は設定とトークンのみで、コードの永続化は Gist 自動保存が担っている)。
  汎用ストア `idb-store.ts` は流用できる

### 3.2 保存・バージョン管理

- 正本は**作者自身の GitHub Gist** (OAuth scope=gist)。サービス運営アカウントに集約しない
- 再実行のたびに debounce しつつ Gist を PATCH → リビジョンが自然に履歴になる
- D1 にメタデータ (タイトル・説明・タグ・公開範囲・統計) とアセット台帳を持つハイブリッド構成 (ADR 0002)
- キャッシュ (R2/KV) が GitHub 障害時のレプリカを兼ねる
- 過去リビジョンの閲覧: マニフェストごと解決するため当時のアセットで再現できる

### 3.3 アセット

- 対応形式 (初期 allowlist): 画像 png/jpg/gif/webp・3D obj/gltf/glb・音声 mp3/wav/ogg・データ json/csv/txt・フォント otf/ttf
- SVG / HTML は XSS ベクタのため初期は除外
- クォータ: 1 ファイル 5MB / ユーザー合計 250MB (無料)。**値はユーザー単位の設定値として持ち、有料プランで引き上げられる構造にする** (プラン内容は将来検討)
- content-addressed storage: sha256 キーの不変 blob (R2) + Gist 内 assets.json で参照 (ADR 0003)
- コード内は相対ファイル名のまま (`loadImage("cat.png")`)。実行時にマニフェストで URL 解決
- アップロードは Worker 経由で検証 (sha256 / MIME / クォータ)。既存 blob は転送スキップ (dedup)

### 3.4 閲覧・共有

- 作品ページ: 実行 + コード表示 + メタ情報。閲覧はログイン不要。
  URL は `/@<login>/<sketchId>` (正典) と `/s/<sketchId>` (login に依存しない恒久リンク)。
  **引く鍵は sketchId だけで login は飾り**なので、作者が改名しても古いリンクが生きる (ADR 0011)
- **準リアルタイム同期閲覧**: 作者の再実行 (Gist リビジョン作成) を数秒〜10 秒の遅延で閲覧者の画面に反映する。経路はエディタ → バックエンド通知 → SSE/WebSocket 配信。完全なリアルタイム性は不要。共同編集はスコープ外
- 公開範囲: **public** (公開 Gist) / **限定公開** (secret gist。「URL を知る人は誰でも見られる = private ではない」注意書き必須) の 2 段階。真の非公開は要件から除外
- フォーク: **系譜の正典は D1** に置き、GitHub 側のリンクはボーナスとして扱う (ADR 0018)。
  他人の作品は Gist fork API (blob は共有 = コピー不要の O(1)、`Forked from` が付く)、
  自分の作品からの派生は新規 Gist の作成 (**自分の Gist は自分で fork できない** — #44)。
  複製されるのは常に最新の版で、公開範囲は元を引き継ぐ (Gist の制約)
- サムネイル: 実行キャンバスから自動取得 (作者のエディタが保存のたびに撮る) → R2 保存。
  canvastage に相当するブリッジは無く新規に作った (別オリジン iframe からの取得なので
  postMessage 越しになる — ADR 0019)。**配るのは 1 枚だけで、変換は挟まない** —
  撮る側で長辺 1200px に正規化する。当初は Cloudflare Images でのリサイズ配信を
  想定していたが、今要るサイズは作品ページの OGP 1 つで、変換の課金と設定に見合わない。
  複数サイズが要るのは作品一覧の器ができてから (Phase 5) で、元の 1 枚は R2 にある

### 3.5 発見 (ギャラリー)

- 全ユーザー横断の作品一覧 (新着など)
- 検索・タグによる絞り込み
- ユーザーページ (作者ごとの作品一覧)

### 3.6 認証

- GitHub OAuth のみ (作者に必要。閲覧者は不要)
- gist scope は**ユーザーの全 Gist への書き込み権限**になるため、ログイン時にその旨を明示し、「本サービスが操作するのは本サービスで作成した Gist のみ」とポリシー宣言する

## 4. v2 以降 (スコープ外。ただし設計で妨げない)

- いいね・コメント・フォローなどのコミュニティ機能
- チュートリアル機能・教育向けクラス機能
- 有料プラン (クォータ拡大に加え、より良い付加価値を検討したい)
- OpenProcessing への書き出し (canvastage 資産の移植)
- 外部サイトへの embed (モデレーション・abuse 対策とセットで)

## 5. 非機能要件

### 5.1 セキュリティ

- 他者コードの自動実行があるため、**実行は必ず別オリジン** + sandbox iframe + postMessage (origin 検証)。本体サイトのセッション・トークンから隔離する
- アセット配信も本体と別オリジン (例: assets ドメイン)、`X-Content-Type-Options: nosniff` 付与
- p5.js Web Editor の教訓: モデレーション無しの全画面 embed はフィッシングに悪用される。v1 の実行面は自ドメイン内の作品ページに限定

### 5.2 GitHub 規約遵守 (Gist 正本の成立条件)

- 閲覧者トラフィックを GitHub (API / raw) に直接流さない。配信は自前キャッシュから。
  **閲覧経路では GitHub を 1 回も叩かない** (D1 のポインタ → R2 の不変オブジェクト)。
  GitHub の消費は閲覧数ではなく保存回数に比例する (ADR 0011)
- 書き込みは各ユーザー自身のトークンで行い、レート制限を遵守 (mutative は 1 req/s 以上の間隔、content-generating 80 req/分)
- 未認証アクセス (60 req/h/IP・raw 直リンク) に依存しない。**公開情報の読み出しは
  OAuth App の client credentials (Basic 認証) で行う** — 匿名 60 req/h/IP に対し
  5,000 req/h/app で、Workers の共有出口 IP に左右されない
- conditional GET (ETag) を活用する (304 はレート消費ゼロ。ただし**認可済みの要求に限る**)。リビジョン SHA 付き内容は不変なので永続キャッシュする

### 5.3 可用性

- キャッシュを実質レプリカとして保持し、GitHub 障害・レート制限時も閲覧を継続できる
- 作品はユーザー自身の Gist にあるため、サービス都合のロックインが構造的に無い (エクスポート経路を兼ねる)

### 5.4 abuse 対策

- 形式 allowlist・サイズ / クォータの二重制限
- Cloudflare CSAM Scanning Tool の有効化、WAF / rate limit、hotlink (外部サイトの CDN としての利用) 禁止の規約明記
- 孤児 blob の GC: D1 の参照カウント + 猶予期間。**公開済みリビジョンが参照する blob は原則削除しない** (過去リビジョン再現の保証)

## 6. 制約・前提

- Gist の制約: テキストのみ・フラット (フォルダ無し)・API は 1 ファイル 1MB で truncated (サービス側で 1MB 以下を強制し API 完結)・300 ファイル上限・**中身が空 (空白のみ) のファイルは作れない** (422)・**公開範囲は作成時に固定** (public / secret を後から変更できない → ADR 0010)
- Gist に webhook は無い。更新検出は「自サービスのエディタが PATCH 時にバックエンドへ通知」+「表示時の conditional GET」+「404 時の tombstone 処理」(ユーザーは GitHub 側で直接削除できる)
- インフラは Cloudflare (ADR 0001)。配信は Workers の static assets (ADR 0006)。
  egress 無料が「バズっても転送費ゼロ」を構造的に保証する
- フロントエンドは Astro + islands (ADR 0004)、リポジトリは npm workspaces のモノレポ (ADR 0005)
